Invoke the `writing-pr-descriptions` skill.

- Compare the branch against trunk (not just the last commit) to get the full scope of changes.
- Write a description with four sections: What it does, Rationale, Implementation, Testing instructions.
- Follow the skill's guidelines: be specific, use inline `code`, show code examples for complex changes, avoid buzzwords and emojis.
